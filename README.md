# 国际剧目译演发布

本项目提供国际剧目译演发布的服务端领域基础：从一次首演扩展为常态化国际演出时，
让故事片段、中文原稿、翻译分支、文化说明、亲历者许可、角色版本、场次编排和发布渠道
形成可追溯关系，并在字幕、授权、排班、改词由不同人员维护的情况下保证观众看到的
每一句字幕都经过应有的确认。

## 目录

- `src/domain.js` 领域实体与输入校验（片段、原稿、分支、修订、许可、角色、场次、渠道等）。
- `src/clock.js` 可控时钟：系统时钟与可手动推进的测试时钟。
- `src/repository.js` 事件溯源仓库：事件只增不改，可选 JSONL 日志持久化。
- `src/service.js` 应用服务：登记、修订、合议、复核、锁定、冻结、发布包与追溯。
- `contracts/record.json` 既有登记输入契约；`contracts/release.json` 译演发布服务契约。
- `data/sample.json` 本地冒烟数据。
- `tests/` 覆盖登记、修订、合议、复核、锁定、取消、换角、撤回、发布与断点续跑。

## 关键规则

- **并行修订与幂等**：译者在各自分支并行提交；重复提交同一 `revision_id` 且内容一致时
  返回首次结果，内容不同则拒绝。
- **内容冲突合议**：同一台词行被不同内容从同一基点推进时进入合议，
  由决定人裁定胜出修订或合并出新译文后才生效。
- **敏感改动复核**：涉及史实（`involves_history`）或人物身份（`involves_identity`）的
  修订必须经对应类别复核人批准，且不得标记为兼容修订。
- **锁定场次**：发布包生成即锁定场次，此后仅接收 `change_kind: "compatible"` 的修订；
  兼容修订生效后就绪包自动失效并重排生成。
- **冻结而非抹去**：演出取消、换角、授权撤回只冻结未来使用——未来场次的就绪包失效、
  重生成时剔除被冻结内容；已发生的演出与发布记录全部保留。
- **可控时钟发布**：`tick()` 按注入时钟在开演前（`packageLeadMs`）为每个场次生成唯一
  发布包（`pkg-<场次>-<序号>`，含内容哈希与演员表快照）。
- **断点续跑**：以 `journalPath` 打开仓库后事件落盘；进程重启用 `Service.open()` 恢复，
  `resume()` 重新排队失败任务并继续未完成的发布任务。

## 追溯接口

`explainSubtitle(performance_id, line_id)` 说明某句字幕：

- 采用了哪版原稿（`manuscript`）与哪个翻译分支、哪次修订（`revision_id`）；
- 谁批准（`approvals`：复核人、类别、时间）；
- 在哪些场次生效（`effective_performances`）；
- 撤回后受到什么影响（`withdrawal_impact`：被冻结的未来场次与保留的历史场次）。

## 运行

运行测试：`npm test`

检查源码：`npm run build`

验证样例：`npm run check:sample`

端到端演示（登记 → 敏感修订复核 → 时钟驱动生成发布包 → 撤回冻结 → 字幕追溯）：
`node src/cli.js demo`

项目只使用 Node.js 内置模块，不需要连接其他运行服务。
